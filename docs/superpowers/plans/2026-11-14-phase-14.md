# Phase 14: humanoid rigging

Implement the roadmap's humanoid auto-rig, adjustable guides, bone editing, weight visualization, pose testing and versioned rig outputs with explicit clip handling.

Use a separate built-in headless Blender engine via the existing queue. A fixed humanoid guide schema uses bounded numeric parameters (no arbitrary executable payload or new IPC). Guides are normalized to the source bounding box, with glTF Y up and +Z front. Auto-rig expects a standing humanoid in T/A pose; it does not infer anatomy from arbitrary geometry. Blender heat weights must be real and validated; failures never publish fabricated fallback weights. Edit one selected existing joint's rest position per candidate. Existing animation clips can only be preserved when the existing rig remains compatible; replacing a skeleton requires explicit discard. Pose testing changes the viewer only.

- [x] Blender engine: bounded guides, real armature/weights, rest-joint edits, explicit preserve/discard, safe embedded GLB input, real Blender fixtures and deformation checks.
- [x] Renderer rig metadata, guide/skeleton overlays, selected-bone weight colors and reversible pose testing, clean source/session transitions.
- [x] Session-scoped rig store and Kivora controls with en/es translations; pin queue parents and publish preview rig variants.
- [x] Electron tests of auto-rig/edit/pose/weights/clip policy and original preservation; independent security/correctness review.
- [x] Typecheck, lint, build, relevant regression suite, manuals and phase status.

Review focus: coordinate conversion and normalized bounds; actual skin deformation and normalized weights; missing/duplicate bones and unsupported inputs; preserving clips rather than silently retargeting; source/session races and interaction with paint/material overlays.
